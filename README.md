# TBAS — Edge 标签页快照与环境切换

把 Edge 里越开越多的分组标签页，保存成一份**可检索、可选择性恢复、可安全关闭**的本地快照。

周五下班：保存 → 关闭 → 释放内存。  
周一上班：打开面板 → 选择分组或标签 → 恢复。  
浏览器、电脑关掉之后，快照仍在。

> 截图未随仓库发布（其中包含内部系统的域名与工单号）。

---

## 它解决什么问题

| 场景 | 以前的麻烦 | TBAS 的做法 |
| --- | --- | --- |
| 分组越来越多 | 标签栏放不下，找东西靠翻 | 保存成快照，按环境、分组、标题、URL 搜索 |
| 办公 / 个人切换 | 周五关掉办公标签，周一无法还原分组 | 每份快照带环境标签，一键归档 / 恢复 |
| 内存占用高 | 几十上百个标签一直挂着 | 快照落盘后「保存并关闭」，释放内存 |
| 关电脑后想回顾 | 浏览器历史混乱，分组信息丢失 | 本地快照 + 离线 HTML 报告，不依赖浏览器在线 |
| 重复标签 | 同一页面开好几次 | 保存时去重，识别 utm 等跟踪参数 |

TBAS 不是「标签页休眠器」，也不是云同步服务。它做的是**快照**：记录窗口、分组、颜色、折叠状态、固定标签、标签顺序和当前标签，然后在你需要时重建它们。

---

## 功能一览

- **完整采集**：窗口、分组名称与颜色、折叠状态、固定标签、标签顺序、当前标签、标题、URL。
- **环境（Environment）**：内置「办公 / 个人」，可自定义；采集时选择环境，列表可按环境筛选。
- **快速保存**：工具栏打开面板，`⌘S` / `Ctrl+S` 保存整个范围。
- **保存前手动选择**：勾选想要的窗口、分组或单个标签，只保存这一部分；也可以只关闭所选标签。
- **分组折叠**：像 Edge 一样点组名或箭头折叠整组，支持「全部折叠 / 全部展开」；选择器和快照详情都可用。
- **保存并关闭**：快照先落盘，再关闭除面板外的窗口，立刻释放内存。
- **选择性恢复**：整个快照、某个分组、单个标签；恢复到新窗口或当前窗口。
- **语义去重**：同一窗口内相同网址只保留一个，固定 / 当前状态合并到保留项。
- **快照管理**：重命名、删除、导入、导出、HTML 报告、JSON 备份。
- **离线 CLI**：`list / show / search / stats / report / export / open / scan / doctor`，不需要浏览器。
- **本地优先**：没有服务器、没有遥测、没有 Host 权限，不读取网页内容。

## 安装扩展（约 2 分钟）

要求：Microsoft Edge 110+（本项目在 Edge 155 / macOS 上验证）。无需构建，无需 npm。

1. 打开 Edge，地址栏输入 `edge://extensions`。
2. 打开左下角「开发人员模式」。
3. 点击「加载解压缩的扩展」，选择本仓库的 **`extension/`** 目录（里面直接有 `manifest.json`）。
4. 在工具栏的扩展列表里固定 **TBAS**，点击图标打开面板。
5. 可选：按 `Alt+Shift+T` 随时打开 TBAS。

> 第一次安装时，TBAS 会自动打开面板。扩展没有内容脚本，也不会注入任何网页。

安装后可以先点击面板底部的「载入示例」，看看快照、分组和恢复操作长什么样。

## 5 分钟上手

### 保存

1. 在「保存到环境」里选择 **办公** 或 **个人**。
2. 快照名称可以留空，系统会自动命名为「办公 · 10-17 18:10」。
3. 选择范围：**所有窗口** 或 **当前窗口**。
4. 需要清理重复页时勾选「保存时去重」。
5. 点击 **保存快照**（`⌘S` / `Ctrl+S`）。
6. 保存后会自动展开这份快照，可以直接检查分组。

### 只保存一部分（手动选择）

1. 在面板里填好环境和名称，点击 **选择标签…**。
2. TBAS 会读取当前范围内的实时标签页，弹出一棵可选择树：
   - 勾选/取消整个窗口；
   - 勾选/取消某个分组；
   - 或逐个勾选标签。未勾选的不会写入快照；
   - 点分组左侧的箭头或组名可以**折叠整组**，工具条还有「全部折叠 / 全部展开」。
3. 点击 **保存所选**：只保存勾选的部分，浏览器里其他标签保持打开。
4. 点击 **保存并关闭所选**：保存后只关闭勾选的标签，未勾选的标签会保留下来。

> 环境、名称和「保存时去重」都沿用面板上的设置。内部页（`edge://` 等）可以保存到快照，但恢复时会被跳过。  
> 折叠只影响当前查看：快照中每个分组是否折叠，仍按采集时 Edge 里的实际状态保存和恢复。

### 查看与恢复

1. 在快照列表里点击标题或 **查看**，展开窗口 → 分组 → 标签。
   - 点分组箭头或组名可折叠/展开整组；详情工具条有「全部折叠 / 全部展开」。
2. 默认勾选所有可恢复标签；可以取消勾选，或按分组 / 窗口勾选。
3. 在「恢复到」里选择 **新窗口** 或 **当前窗口**。
4. 点击 **恢复所选**；也可以点击某个分组右侧的 **恢复本组**。
5. 恢复后，Edge 会按原顺序创建标签，并重建分组名称、颜色、折叠状态、固定状态和当前标签。

### 保存并关闭（释放内存）

1. 确认顶部环境正确。
2. 点击 **保存并关闭**。
3. 阅读确认框里的窗口数、标签数和内存粗略估算，点击确认。
4. TBAS 先保存快照，然后关闭除本面板外的所有标签页；面板会保留，方便你看到归档结果。
5. 如果有未提交的表单，Edge 可能会弹出离开确认。

### 环境切换

- 面板顶部选择「办公 / 个人」，决定新快照归到哪个环境。
- 列表上方的环境筛选可以只看某一类快照。
- 在 **设置 → 环境** 里可以增删自定义环境（例如「客户现场」「学习」）。

## 周五 / 周一工作流

**周五 18:00**

1. 打开 TBAS → 环境选「办公」。
2. 点击 **保存并关闭** → 确认。
3. 看到「已归档并关闭 N 个标签页」后，直接关浏览器 / 电脑。

**周一 09:30**

1. 打开 Edge → 点击 TBAS。
2. 环境筛选选「办公」，找到周五的快照。
3. 只想继续一部分：展开后取消不需要的分组；或直接点某个分组的 **恢复本组**。
4. 想全部继续：点 **恢复全部**。
5. 如果周一还有别的窗口在用，把「恢复到」切换成 **当前窗口**，所选标签会合并进当前窗口。

**周末个人使用**

- 切换到「个人」环境保存 / 恢复，互不干扰。
- 两份快照可以同时在列表里，靠环境筛选区分。

## 数据保存在哪里

### 扩展存储

- 使用 `chrome.storage.local`，数据跟着 Edge 的浏览器 profile 走。
- 索引：`tbas.index.v1`（轻量元数据，列表不会加载全部标签）。
- 快照：`tbas.snapshot.<id>`（完整快照）。
- 设置：`tbas.settings.v1`。

### 自动备份（推荐开启）

设置 →「自动备份到下载文件夹」后，每次保存会额外写入：

```text
~/Downloads/tbas-snapshots/<环境>/<YYYYMMDD-HHmm>-<名称>.json
```

这是普通的 JSON 文件，可以用 Git、网盘、`gzip` 或任何备份工具管理。  
卸载扩展、清除浏览器数据会删除扩展存储，但**不会**删除这些已导出的文件。

### 手动导出

- 单份快照：展开 → **导出 JSON**。
- 单份报告：展开 → **导出 HTML 报告**。
- 全部快照：顶部 **导出全部**，得到 `tbas.bundle` JSON。
- 导入：顶部 **导入**，支持单份快照、bundle 或快照数组；ID 冲突会自动生成新 ID 并加「（导入）」后缀。

### CLI 数据目录

```text
~/.tbas/
  snapshots/
    <id>.json
```

可用 `TBAS_HOME` 覆盖，例如 `TBAS_HOME=/tmp/tbas`。

`tbas scan` 会递归扫描 `~/Downloads/tbas-snapshots/`（以及 `TBAS_BACKUP_DIR`），把备份文件导入 `~/.tbas/snapshots/`；已存在的 ID 默认跳过，`--replace` 覆盖。

> CLI 只读写自己的 `~/.tbas` 目录，**不会直接写入 Edge 的扩展存储**。要把 CLI / 另一台电脑上的 JSON 带回扩展面板，请使用面板顶部的「导入」。

## 什么是「压缩」

TBAS 的压缩是**语义压缩**，不是把网页打包成 zip：

1. **去重**：同一窗口内相同网址只保留一个；`?utm_source=...`、`fbclid` 等跟踪参数会被忽略后再比较。保留项会继承被删除项的固定 / 当前状态。
2. **只存元数据**：快照只包含 URL、标题、分组、顺序等，不保存网页正文、图片或缓存。示例中 18 个标签的 JSON 约 6 KB，通常每个标签不到 1 KB。
3. **关闭释放内存**：真正占内存的是浏览器里打开的页面，所以「保存并关闭」比压缩文件更有效。
4. **可选文件压缩**：导出的 JSON 可以直接 `gzip`；离线 HTML 报告本身是单文件、无外部依赖。

> 内存估算按每标签约 80 MB 粗略计算，仅用于提示，实际取决于页面内容。

## CLI

CLI 是扩展的离线伴侣：查看、搜索、导出报告、从备份导入，以及在不想用扩展时把网址重新交给 Edge。

要求 Node.js 20+，零依赖。

```bash
# 方式一：直接运行
node bin/tbas.mjs help

# 方式二：安装为全局命令
npm link
tbas help
```

### 命令

| 命令 | 说明 |
| --- | --- |
| `tbas list [--env 办公] [--json]` | 列出快照（ID、名称、环境、窗口/组/标签、时间） |
| `tbas show <ID\|前缀\|名称> [--json] [--urls] [--md]` | 查看分组树；可输出 JSON、网址列表或 Markdown |
| `tbas search <关键词…> [--limit 50] [--env] [--json]` | 跨快照搜索标题、URL、分组 |
| `tbas stats [--json]` | 快照数、标签数、唯一网址、重复数、环境分布 |
| `tbas import <文件或目录…> [--replace]` | 导入单快照 / bundle / 数组 |
| `tbas scan [--dir <目录>] [--replace]` | 扫描自动备份目录并导入 |
| `tbas export <ID> [--html\|--md\|--json\|--urls] [文件]` | 导出单份快照 |
| `tbas report [--out <文件>] [--env] [--open]` | 生成全部快照的离线 HTML 报告 |
| `tbas open <ID> [--group <名称>] [--window w1] [--dry-run]` | 用 Edge 打开快照网址（**不恢复分组**） |
| `tbas rm <ID> --yes` | 删除一份快照 |
| `tbas demo [--out <目录>]` | 生成两份示例快照 |
| `tbas doctor [--json]` | 检查 Node、数据目录、Edge、扩展完整性 |

### 常用示例

```bash
# 生成示例并打开离线报告
tbas demo
tbas report --open

# 从扩展的自动备份导入
tbas scan

# 查看一个快照的分组树
tbas show demo-office-v1

# 搜索「周报」，只看前 20 条
tbas search 周报 --limit 20

# 导出单份 HTML 报告到桌面
tbas export demo-office-v1 --html ~/Desktop/tbas-office.html

# 只打开「项目」分组里的网址，先 dry-run 看命令
tbas open demo-office-v1 --group 项目 --dry-run
tbas open demo-office-v1 --group 项目

# 检查环境
tbas doctor
```

`tbas open` 只把 URL 交给 Edge，**不会**恢复分组；要完整恢复分组、颜色、固定状态，请使用扩展面板。`--dry-run` 会打印实际会执行的 `open` / `start` / `xdg-open` 命令。

### 离线报告

`tbas report` 生成一个完全自包含的 HTML 文件：无外部字体、无 CDN、无脚本请求，支持搜索、环境筛选、按组复制链接、展开/收起。适合归档、发给同事或放到网盘。

## 快照格式

一份快照就是一个普通 JSON 对象（`schema: "tbas.snapshot"`，当前 `version: 1`）：

```json
{
  "schema": "tbas.snapshot",
  "version": 1,
  "id": "snap-20251017-181000-a1b2",
  "name": "办公 · 周五下班",
  "env": "office",
  "tags": ["周五"],
  "createdAt": "2025-10-17T10:10:00.000Z",
  "source": {
    "browser": "Edge",
    "extensionVersion": "0.1.0"
  },
  "stats": {
    "windows": 2,
    "groups": 5,
    "tabs": 18,
    "pinned": 1,
    "restorable": 17,
    "unrestorable": 1,
    "uniqueTabs": 17,
    "duplicates": 1
  },
  "windows": [
    {
      "key": "w1",
      "focused": true,
      "groups": [
        { "key": "g1", "title": "项目 · 客户门户", "color": "blue", "collapsed": false }
      ],
      "tabs": [
        {
          "key": "t1",
          "url": "https://jira.example.com/browse/TBAS-1",
          "title": "TBAS-1 · Jira",
          "pinned": true,
          "active": true,
          "group": "g1",
          "restorable": true
        }
      ]
    }
  ]
}
```

- `windows[].groups` 只保存实际有标签的分组。
- `tabs[].group` 是窗口内的分组 key，`null` 表示未分组。
- `restorable` 由 URL 协议决定：`http/https/file` 可恢复；`edge://`、`chrome://`、`about:`、`data:`、`javascript:` 等不可恢复。
- 导入时会重新校验、清洗 key、限制长度并重算统计，损坏字段不会破坏 UI。

## 工作原理

```text
Edge 标签页 / 分组
        │  chrome.tabs / chrome.tabGroups
        ▼
 lib/engine.js  ── capture ──►  lib/core.js  ── buildSnapshot ──►  chrome.storage.local
                                       │                              │
                                       │                              ├── 自动备份 JSON（可选）
                                       │                              └── 导入 / 导出 / CLI
                                       ▼
                               buildRestorePlan
                                       │
                                       ▼
                         engine.restore → Edge 新窗口 / 当前窗口
```

### 恢复算法

1. 按快照选中项生成恢复计划；不可恢复的浏览器内部页被跳过并报告。
2. 每个快照窗口创建一个新的 Edge 窗口（或复用当前窗口）。
3. 按原顺序逐个创建标签；固定标签在创建时设置 `pinned`。
4. 把连续属于同一分组的标签交给 `chrome.tabs.group`，再用 `chrome.tabGroups.update` 恢复标题、颜色、折叠状态。
5. 删除新窗口里的临时空白页，恢复当前标签，必要时聚焦原主窗口。

### 为什么需要「先取消固定再关窗口」

在无头 Edge 的自动化验证中发现：对**包含固定标签的窗口**调用 `chrome.windows.remove()` 会返回成功，但窗口实际没有关闭。TBAS 在关闭前先取消这些窗口里的固定状态，并在调用后再次查询窗口是否存在；如果仍然存在，则退回到逐个关闭标签。这个兜底逻辑在真实 Edge（包括普通桌面窗口）同样安全。

### 权限说明

| 权限 | 用途 |
| --- | --- |
| `tabs` | 读取标签的 URL、标题、固定/当前状态，创建和关闭标签 |
| `tabGroups` | 读取和重建分组名称、颜色、折叠状态 |
| `storage` / `unlimitedStorage` | 本地保存快照 |
| `downloads` | 导出 JSON / HTML、自动备份 |

**没有** `host_permissions`，**没有** `content_scripts`，**没有** `scripting`，不加载远程代码。TBAS 看不到网页内容，只能看到浏览器暴露的标签页元数据。

## 限制与边界

- **浏览器内部页不能恢复**：`edge://settings`、`edge://extensions`、扩展页面等不允许扩展重新打开。它们会保留在快照 JSON / 报告里，可复制 URL 后手动打开。
- **不保存页面状态**：滚动位置、表单内容、登录态、页面内 JS 状态都不在快照里。登录态由 Edge profile 维持。
- **不采集无痕窗口**。
- **不保存窗口位置 / 大小 / 显示器布局**，恢复时使用 Edge 默认窗口。
- **恢复大量标签需要时间**：逐个创建，面板会显示进度；Edge 可能把后台标签置为睡眠状态。
- **关闭时有未提交表单**：Edge 可能弹出确认，导致部分窗口没有关闭，面板会提示错误。
- **CLI 的 `open` 不恢复分组**；完整恢复必须用扩展。
- **Edge Workspaces / Collections** 不在采集范围内。
- **数据跟随 profile**：卸载扩展、清除扩展数据会删除 `chrome.storage.local` 中的快照；建议开启自动备份或定期「导出全部」。
- **单机本地**：没有跨设备同步；可以用网盘同步导出的 JSON。
- 本项目是个人工具，不是 Microsoft Edge 官方功能。

## 故障排除

| 现象 | 原因 / 处理 |
| --- | --- |
| 扩展加载失败 | 确认选择的是 `extension/` 目录，且 `manifest.json`、`icons/` 存在；在 `edge://extensions` 点「重新加载」 |
| 「保存快照」是灰的 | 当前可保存标签为 0（例如只有 TBAS 面板）。打开一些标签页，或切换到别的窗口 |
| 恢复后没有分组 | 使用的是 CLI `open`，它只能打开 URL。请在扩展面板恢复 |
| 恢复时提示内部页未恢复 | `edge://` / 扩展页无法由扩展重新打开，属预期行为；可从报告复制链接 |
| 自动备份找不到 | 检查设置是否开启；路径为 `~/Downloads/tbas-snapshots/`；也可 `tbas scan --dir <目录>` |
| `tbas: command not found` | 使用 `node bin/tbas.mjs …`，或先 `npm link` |
| 快照全没了 | 扩展存储会随卸载/清除数据删除；检查自动备份目录，或之前导出的 JSON |
| `tbas doctor` 提示扩展文件缺失 | 从仓库重新拉取 `extension/` 目录，或检查是否误删 `demo.json` / 图标 |
| E2E 超时 | 关闭其他 Edge 自动化实例；确认没有进程占用调试端口；重试 |

## 开发

```text
extension/
  manifest.json          MV3 清单（无 Host 权限）
  background.js          工具栏 / 快捷键打开面板
  dashboard.html/css/js  扩展面板
  storage.js             chrome.storage.local 持久化
  demo.json              内置示例（由 src/demo.js 生成）
  lib/
    core.js              纯逻辑：快照模型、校验、去重、搜索、恢复计划、报告渲染
    engine.js            chrome.tabs / tabGroups 适配层
  icons/
bin/tbas.mjs             离线 CLI
src/demo.js              示例快照
test/
  core.test.mjs
  engine.test.mjs
  cli.test.mjs
  e2e/extension.e2e.mjs
scripts/
  check.mjs              静态检查
  make-icons.mjs         无依赖生成 PNG 图标
  sync-demo.mjs          重新生成 extension/demo.json
docs/                    截图与说明资源
```

常用开发命令：

```bash
npm test             # 单元 + CLI 测试
npm run test:e2e     # 真实 Edge 端到端
npm run check        # 静态检查
npm run demo         # 生成 CLI 示例快照
npm run demo:sync    # src/demo.js → extension/demo.json
npm run icons        # 重新生成图标
```

`core.js` 不依赖任何浏览器 API，因此同一套快照、校验、去重和报告逻辑同时供扩展与 CLI 使用。修改快照格式时，请同时更新 `SNAPSHOT_VERSION`、校验逻辑和测试。
